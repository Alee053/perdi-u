## Variables actuales

| Variable                                       | Consumidor y visibilidad                           | Ejemplo sin secretos                                                          |
| ---------------------------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------- |
| `POSTGRES_PASSWORD`                            | Compose local; secreta.                            | Definir una contraseña local propia en `.env`.                                |
| `POSTGRES_PORT`                                | Compose local; opcional.                           | `5433` por defecto; si lo cambias, usa el mismo puerto en `DATABASE_URL`.     |
| `DATABASE_URL`                                 | API y mantenimiento de BD; secreta.                | Formato en [`.env.example`](../.env.example), contraseña codificada para URL. |
| `PORT`, `HOST`                                 | API; configuración de proceso.                     | `3000`, `127.0.0.1`.                                                          |
| `VITE_API_BASE_URL`                            | Bundle web; pública.                               | `/api`.                                                                       |
| `API_PROXY_TARGET`                             | Proceso Vite; no se incorpora al bundle.           | `http://127.0.0.1:3000`.                                                      |
| `CHROMIUM_PATH`                                | Runner de aceptación; opcional.                    | Ruta del navegador instalado; CI usa el Chromium de Playwright.               |
| `TEST_DATABASE_URL`, `PERDIU_TEST_CONTAINER`   | Internas del runner; no configurarlas manualmente. | Se generan para cada contenedor aislado.                                      |
| `AUTH_*`, `VITE_AUTH_URL`, `AUTH_PROXY_TARGET` | Auth, API y web; ver [la guía de Auth](auth.md).   | `pnpm auth:keys` genera los secretos; la API solo recibe URLs públicas.       |
| `R2_ACCOUNT_ID`, `R2_BUCKET_NAME`              | API; configuración del endpoint y bucket.          | Solo para un bucket privado de desarrollo autorizado.                         |
| `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`     | API; credenciales secretas de acceso al bucket.    | Limitar permisos al bucket de desarrollo; nunca usar prefijo `VITE_`.         |

La API/CLI leen `.env` raíz. Vite lee `apps/web/.env`; copiar su [ejemplo](../apps/web/.env.example) solo si hace falta cambiar los valores por defecto. R2 es opcional para arrancar la API: las cuatro variables deben estar presentes juntas para habilitar fotos; una configuración parcial detiene el arranque con un mensaje sin secretos. Sin configuración completa, las rutas de fotos responden `503`. Un prefijo `VITE_` hace pública la variable: nunca usarlo para credenciales de BD, claves administrativas o secretos del proveedor.

Configura el endpoint con el `R2_ACCOUNT_ID`, un bucket existente y una clave de API con permisos de lectura/escritura de objetos limitada a ese bucket. El adapter usa `region: auto` y el endpoint S3 `https://<account-id>.r2.cloudflarestorage.com`, según la [guía oficial de Cloudflare para AWS SDK v3](https://developers.cloudflare.com/r2/examples/aws/aws-sdk-js-v3/) y [compatibilidad S3](https://developers.cloudflare.com/r2/get-started/s3/). Mantén el bucket privado: la API transmite fotos solo después de asociarlas a un reporte. No se emiten URLs públicas ni URLs firmadas.

Los objetos usan la clave interna `report-media/<id-generado>` y la base guarda su propietario, tipo, tamaño y estado. El navegador recibe solo el ID opaco y las URLs del API para fotos ya asociadas. El dueño puede borrar medios propios aún no asociados con `DELETE /media/:id`; una asociación impide borrarlos. No hay job de limpieza: la interfaz intenta borrar archivos quitados o abandonados al cerrar el formulario. Para una interrupción, una persona autorizada revisa `report_media` sin `report_id` y con `created_at` antiguo, borra cada objeto en el bucket privado y luego su fila; nunca borra filas asociadas. Los objetos huérfanos sin fila por fallo al guardar metadatos requieren inspección manual del prefijo privado del bucket. No exponer las claves.

Auth por correo está documentado en [su guía](auth.md). Para Google OAuth, documentar nombres/env, URLs de callback, accesos y responsables al implementarlo. No inventar variables que el código todavía no consume ni copiar secretos a Git. Si falta acceso real para la aceptación de un proveedor, registrar el bloqueo y mantener la PR Draft. Una simulación no demuestra que el proveedor esté integrado.

El propietario autorizó una demo aislada en `tars-vps:/opt/stacks/perdi-u`, con dominio de backend `perdi-u-api.alecastro.dev`. Su [guía](deployment.md) define configuración, NPM, operación manual, confirmación privada de cuentas y retirada; no hay CD del backend. El Compose raíz y los runners de aceptación siguen siendo locales y los datos sembrados son ficticios. Otros despliegues, servicios de pago, importaciones de datos o cambios en entornos compartidos necesitan su propia autorización.
